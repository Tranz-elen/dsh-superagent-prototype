- `assignedPromptRevision` hashes the ticket id with FNV-1a (`hash`: start at `0x811c9dc5`, XOR each char code, multiply by `0x01000193` with `Math.imul`, return unsigned) and picks `experiment.revisions[hash(ticketId) % 2]`, so under a fixed experiment a ticket's revision depends only on its id and is the same across processes, hosts and retries.
- It applies in `prepare` when a newly accepted ticket has no numeric `promptRevision` in its trigger meta and `executor.promptExperiment` is enabled with exactly two non-negative integer revisions; an explicit pin wins, and a disabled or malformed experiment returns `undefined` so nothing is pinned.
- Failure mode: changing the hash mid-experiment (algorithm, seed or `% 2` modulus) can remap some ticket ids to the other revision and silently move tickets between cohorts, so cross-host or before/after comparisons no longer measure the same ON/OFF split.
- Reviewer check: run `pnpm vitest run tests/prompt-experiment.spec.ts`; it asserts repeated calls return the same revision for each ticket id, both revisions appear across ids, and disabled or malformed experiments return `undefined`, and confirm `prepare` in `src/executor/dsh.ts` passes `ticket.id`.
- Source: `src/app/prompt-experiment.ts` — `hash` (FNV-1a) and `assignedPromptRevision`; called from `prepare` in `src/executor/dsh.ts`.
