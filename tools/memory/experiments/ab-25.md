- A rule's evidence case ids must be unique because support is counted in distinct cases: the same incident cited three times is still one case, while three different cases show repeated behavior.
- It applies whenever a rule document (`rules.json`) is validated before reaching a prompt: `validateRules` requires at least three evidence entries and checks that `new Set(rule.evidence).size` equals `rule.evidence.length` for every rule.
- Failure mode: counting the same case twice — `['a', 'a', 'b']` passes a length-of-three gate while resting on two cases, so duplicate ids must be rejected rather than inflating support.
- Reviewer check: run `node tools/memory/check-rules.mjs --rules tools/memory/rules.json --cases <stateDir>/cases.jsonl`; duplicate ids fail with `rules[i].evidence has duplicate ids` and a passing file prints `rules valid: N rule(s), M evidence case(s)`.
- Source: `tools/memory/rules.mjs`, `validateRules()` evidence branch (`rule.evidence.length < 3`, duplicate-id and `knownCases` checks); CLI `tools/memory/check-rules.mjs`; tests `tests/rules.spec.ts`.
