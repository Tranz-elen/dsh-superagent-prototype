- An ability verdict is a claim that a tool, command, plugin or script is unusable, unreliable or broken ("the tool is broken"), matched by `hasAbilityVerdict`, rather than a named symptom such as a DNS failure, permission error or nonzero exit code.
- It applies whenever failure text could become a reusable lesson: the transcript digest marks each failed tool call with `quarantined: hasAbilityVerdict(detail)`, and the candidate and playbook gates re-check verdict text before any rule is stored.
- Failure mode of storing it as a reusable rule: one transient or environmental failure ("the tool is broken") becomes permanent advice, so later workers avoid a working tool and the real cause is never probed.
- Reviewer check: run `hasAbilityVerdict('the tool is broken')` (true) and `hasAbilityVerdict('ENOENT: no such file or directory')` (false), then pass the verdict failure through `buildFailureCandidates`; it must be counted under `quarantined` with `candidates: []`, never as a rule.
- Source: `tools/memory/failure-signatures.mjs` — file header ("No ability verdict is ever stored") and the `ABILITY_VERDICT` / `hasAbilityVerdict` section; quarantine path in `tools/memory/failure-candidates.mjs` (`buildFailureCandidates`).
