- The prompt experiment is off by default: `executor.promptExperiment.enabled` defaults to `false`, so `assignedPromptRevision` returns `undefined` and a prepared ticket gets no automatic revision pin, leaving its worker on the current prompt revision.
- It applies at ticket `prepare` only when the trigger has no numeric `promptRevision` (an explicit pin wins) and the experiment is enabled with exactly two non-negative integer revisions; the ticket id hash then picks `revisions[hash(ticketId) % 2]`.
- Failure mode: a test that enables the experiment in shared or default settings without restoring it accidentally assigns revisions to unrelated tickets, silently contaminating the default-off path and later A/B cohorts.
