- A rule needs at least three evidence cases so it rests on repeated behavior rather than one vivid ticket: a rule distilled from one or two cases is a guess with a version number, so the validator refuses it until three distinct cases back it.
- The count is checked each time `validateRules` runs, from `check-rules.mjs` against `rules.json` and `cases.jsonl` and from `tests/rules.spec.ts`, before the rules document is accepted.
- Counting the same case twice inflates support: `['a', 'a', 'b']` has length three but rests on two cases, so `validateRules` rejects repeated ids with `rules[i].evidence has duplicate ids`; it cannot detect two different ids describing one incident, so independence still needs review.
- Reviewer check: run `node tools/memory/check-rules.mjs --rules tools/memory/rules.json --cases <stateDir>/cases.jsonl`; it prints `rules valid: N rule(s), M evidence case(s)` and exits 0, or reports `evidence needs at least 3 case ids` / `evidence has duplicate ids` and exits nonzero.
- Sources: `tools/memory/rules.mjs`, `validateRules` (`rule.evidence.length < 3`, duplicate-id and `knownCases` checks); `tests/rules.spec.ts`, "accepts a rule with three known cases" and "rejects fewer than three cases, unknown cases and duplicate ids".
