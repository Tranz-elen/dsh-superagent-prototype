- A case outcome records how a ticket ended: `outcome` is one of `completed`, `merged`, `closed`, `dropped` or `stopped`, read from `ticketOutcome(ticket)` with `'open'` as the fallback.
- It applies only once `ticket.ended` exists: an open ticket exports `outcome: 'open'`, and a `blocked` or `failed` report does not end a ticket, so it records no outcome.
- Failure mode: conflating stopped with failed — a person's stop is `stopped` with `endedBy: 'human'`, and the case model has no `failed` outcome, so writing one mislabels the case and corrupts outcome distributions.
- Reviewer check: run `pnpm vitest run tests/case-export.spec.ts`, then `pnpm memory:export`; every exported line must carry one of the five outcomes (or `open`), match its `endedBy`/`endReason`, and contain no `failed` value.
- Source: `src/app/cases.ts` — `CaseRecord` (`outcome`, `endedBy`, `endReason`, `follows`) and `caseOf` (`outcome: ticketOutcome(ticket) ?? 'open'`, plus the `endedBy`/`endReason` fields).
