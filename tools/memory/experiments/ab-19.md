- An ability verdict is a claim that a tool, command or plugin is unusable, unreliable or broken ("the tool is broken"), matched by `hasAbilityVerdict`, rather than a named symptom such as a DNS, permission or exit-code failure.
- It is quarantined because a verdict is a pseudo-lesson: it is unfalsifiable, names no cause, and would turn one bad environment into a playbook rule that shapes every later ticket.
- Failure mode of storing it: a transient or environmental failure ("command unusable") becomes permanent advice, so workers stop using a working tool and the real cause is never probed.
- Reviewer check: run `validateFailureCandidate` on the candidate and `validatePlaybookText` on the playbook section; both must reject ability-verdict text, and `buildFailureCandidates` must count it under `quarantined`, not `candidates`.
- Source: `tools/memory/failure-signatures.mjs` (`ABILITY_VERDICT`, `hasAbilityVerdict`) and `tools/memory/failure-candidates.mjs` (`buildFailureCandidates`, `validateFailureCandidate`, `validatePlaybookText`).
