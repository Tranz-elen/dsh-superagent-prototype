- `promptRevision` pinning fixes a ticket's worker to one existing prompt version: a local request's explicit `promptRevision` wins, otherwise `executor.promptExperiment` assigns one of its two revisions deterministically from the ticket id.
- It applies when the ticket is accepted and the experiment is enabled with exactly two non-negative integer revisions, or when a local request passes a pin; otherwise the worker follows the current revision.
- Failure mode: a pin to a deleted revision silently falls back to the current version in `Sessions.promptFor`, while `cases.jsonl` still records the pinned number, so a case can be labeled with a revision it did not run.
- Reviewer check: run `node tools/memory/compare-prompt-revisions.mjs --on 5 --off 4`; confirm both arms are populated, local and A/B tickets are excluded by default, and the report warns that small groups (under five) are insufficient.
