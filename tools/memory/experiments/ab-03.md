- A failure signature is a stable `tool:error-class:keys` label for a failed tool result; paths, line numbers, timestamps and ids are stripped, and no ability verdict is stored, only the symptom to investigate.
- It applies when the offline pipeline digests a failed tool result (non-zero exit or `Error:`), so repeated signatures can cluster into one failure candidate.
- Over-broad: an unclassified error with no stable key becomes `tool:error:generic`, so unrelated failures merge and overstate repetition.
- Reviewer check: the same `ENOENT` error with different paths, lines and timestamps must normalize identically, while a curl DNS failure and a deliberate `exit 1` must differ.
- Source: `tools/memory/failure-signatures.mjs`, `normalizeFailureSignature(tool, error)`, called by `session-digest.mjs`.
