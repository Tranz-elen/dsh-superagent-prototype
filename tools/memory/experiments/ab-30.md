- An explicit `promptRevision` on a local request pins that ticket's worker to the chosen existing prompt version, overriding the `executor.promptExperiment` ON/OFF assignment instead of letting the ticket id hash pick one.
- It applies to local requests when the ticket is prepared: `prepare` reads `trigger.meta.promptRevision` and uses it when it is a number; otherwise the experiment's deterministic assignment applies, when enabled with two revisions.
- Mixing manual pins with automatic assignment contaminates the A/B: a pinned ticket still appears in `cases.jsonl` under its chosen revision, but it was never hash-assigned to that arm, so grouped arms mix deliberate overrides with the random split.
- Reviewer check: POST a local request with `promptRevision` set and confirm its case records that version, while a request without the field records the hash-assigned version — the explicit field must win, so check the field and its precedence over the experiment assignment.
