- The distill review artifact is the rule-extraction JSON that `dist/prompt.md` asks for: `rules` (each with `rule`, `scope`, `evidence` case ids, `confidence` and a worker `check`), `candidates` (an `observation`, its `evidence`, and what `needs` to confirm it) and `contradictions`; `distill.mjs` itself writes only `dist/clusters.json`, `dist/prompt.md` and `dist/status.md`, never the model output.
- It applies after `distill.mjs` opens the gate (`>= --min-cases` cases, default 20, one `intent|outcome` cluster with `n>=3`, `>=2` outcomes) and before a reviewed rule is pasted into a prompt section; below the gate only a closed `dist/status.md` is written, so there is nothing to review.
- Failure mode: treating the review artifact as an automatic rule — pasting the generated `rules` into a prompt section without checking that each cites at least three real case ids, so an unevidenced or untrusted rule becomes behavior-shaping prompt text and later workers follow it.
- Reviewer check: check the files distill writes — `dist/status.md` says `# Distillation gate: open`, `dist/clusters.json` holds every cited id inside a cluster with `n>=3`, and `dist/prompt.md` still requires cited, evidence-backed rules; then replay each rule's `check` and reject rules citing fewer than three ids from `dist/clusters.json`.
