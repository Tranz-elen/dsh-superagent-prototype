- Candidate evidence binding is the attachment of a failure candidate to the exact cases that produced it: `buildFailureCandidates` keeps, per repeated signature, a `cases` set of case ids and an `outcomes` set, so the review artifact cites source cases instead of only a repetition count.
- It applies while candidates are built from a corpus: every non-quarantined failure with a signature is grouped by that normalized `signature`, the originating `c.id` is added to that signature's sets, and the binding is emitted only for signatures reaching `FAILURE_MIN_CASES` (2) occurrences.
- Failure mode: citing the wrong case as evidence — a candidate or report can list a case id that never produced that signature (for example, one pulled from a similar-sounding ticket), and `validateFailureCandidate`'s evidence check only requires at least two ids, not that each cited case actually carries the signature.
- Reviewer check: check how evidence cases are attached — open each candidate's `cases` list and confirm every cited id appears in the source corpus with a `trace.failures` entry matching that exact `signature`; reject the candidate if any citation is bound to the wrong signature.
- Source: `tools/memory/failure-candidates.mjs`, `buildFailureCandidates` (the per-signature `cases`/`outcomes` sets, mapped to arrays) and `validateFailureCandidate` (`cases.length` evidence gate).
