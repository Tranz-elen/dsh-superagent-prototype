- The analyze report (`report.md`, default `--out`) contains a per-case table (id, intent, areas, outcome, decision, retries, human follow-ups, title), distributions of outcomes/intents/areas/decision reasons/report states, repetition counts (n>=2 signatures, repeated bash commands, repeated failures, outcome spread), per-case trace digests, decision-only records, and a data-sufficiency verdict.
- Useful before distilling rules: it shows whether the corpus is large and repetitive enough (>=20 cases, one `intent|outcome` signature with n>=3, >=2 repeated failures, >=2 outcomes) and which cases a rule could cite.
- Failure mode: the verdict summarizes whatever input was given, not proof of a real pattern — missing transcripts make `readSession` return `[]`, so repetition can read as clean or absent when the runs were simply unobserved.
- Reviewer check: run `node tools/memory/analyze-cases.mjs --cases <cases.jsonl> --out /tmp/report.md`; require the header `cases:` to equal `wc -l <cases.jsonl>`, at least one trace digest with non-zero steps, and the verdict to agree with the Section 4 have/need line.
