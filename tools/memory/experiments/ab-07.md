- `reviewAfter` is the ISO date by which a rule's cited evidence must be re-reviewed; `expiresAt` is the ISO date after which the rule must no longer be applied. Both are optional fields on a rule.
- A rule becomes invalid once `expiresAt` is at or before the current time, or when either date fails `Date.parse`; an overdue `reviewAfter` also fails validation, so the rules file is rejected before any line reaches a prompt.
- Failure mode: a rule past `expiresAt` keeps sitting in the manually pasted worker-only playbook prompt, so workers apply an obsolete fix after its evidence stopped holding.
- Reviewer check: `node tools/memory/check-rules.mjs` validates `rules.json` against the corpus and prints `rules valid: ...`, or names `rules[i].expiresAt is in the past` / `rules[i].reviewAfter is overdue`; `tests/rules.spec.ts` covers the same rejection.
- Source: `tools/memory/rules.mjs`, `validateRules` (`Date.parse` + `Date.now()` checks on `reviewAfter` and `expiresAt`); `tools/memory/rules.json`, rule `edit-read-first` fields `reviewAfter` (`2026-12-09T00:00:00.000Z`) and `expiresAt` (`2027-02-09T00:00:00.000Z`).
