- A repeated failure count measures recurrence across a corpus: `failureCount` groups every case run's failed tool result by the first 80 characters of its `detail` (the exit-code or error marker plus output prefix), and `repeatedFailures` keeps the groups seen at least twice, so the count is the number of distinct recurring failure groups, not the number of failures.
- It applies during the aggregation step of `analyze-cases.mjs` and is evaluated in section 3 of the report; the corpus is only sufficient for distillation when at least `NEED.repeatedFailure` (2) repeated groups exist, next to repeated `intent|outcome` signatures and outcome spread.
- Failure mode: counting the same pattern across unrelated tasks — grouping is global and keyed only by the 80-character detail prefix, so identical boilerplate (a missing tool, a sandbox or permission error, a common test or network exit) appearing in unrelated tickets merges into one "repeated" group and can be distilled into a rule that fits none of them.
