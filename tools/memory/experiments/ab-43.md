- Path normalization in a failure signature replaces machine-specific paths — Windows drive paths and absolute POSIX paths — with `<path>` before a failed tool result is reduced to its stable `tool:error-class:keys` label.
- It applies when the offline digest classifies a failed tool result (non-zero `[exit code: N]`, or text starting `Error:`/`error:`) and records `normalizeFailureSignature(call.name, text)` for clustering.
- Failure mode: the same error at two different paths yields two signatures, so one repeated failure stays hidden below the repetition threshold instead of clustering.
- Reviewer check: call `normalizeFailureSignature` on the same `ENOENT` text with `C:\work\a.txt` and `/home/me/b.txt`; both must produce the same signature, while a curl DNS failure and a deliberate `exit 1` must differ.
- Source: `tools/memory/failure-signatures.mjs` — the drive-path and POSIX-path replacements in `normalizeFailureSignature(tool, error)`, whose file header states paths, line numbers, timestamps and trace ids are stripped.
