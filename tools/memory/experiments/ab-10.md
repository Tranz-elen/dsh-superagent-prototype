- A local workspace snapshot is a plain copy of the workspace directory into the ticket's own directory (`.work/<name>`), made by `snapshotWorkspace`: `.work`, `.git` and `node_modules` are excluded, files over 5 MiB are skipped, every copied file's sha256 and the skipped list go into `snapshot.json`, and the previous snapshot is removed before copying.
- Used in `prepareDirectory` when the ticket's execution has a `workspacePath` (a local workspace ticket): the worker edits only the snapshot copy, and the ticket never pushes or opens a PR.
- Failure mode: the snapshot is a one-way, point-in-time copy, so it can silently diverge from the workspace — a file edited between the walk and the copy disagrees with its recorded sha256, files over 5 MiB are skipped, and worker edits never reach the source at all, since a re-prepare deletes the copy.
- Reviewer check: from the snapshot directory, `jq -r '.files|to_entries[]|"\(.value)  \(.key)"' snapshot.json | sha256sum -c -` prints `OK` for every entry; a mismatch or a `.skipped[]` entry means the worker did not see the real tree.
