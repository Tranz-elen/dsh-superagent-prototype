- `suggestedScope(tool, symptom)` labels a repeated-failure candidate with its likely owner — `orchestrator`, `environment` or `worker` — as a hint for the human reviewer, never an automatic disposition: an `orchestrator*` tool name wins first, then symptoms mentioning permission/forbidden/rate limit/DNS/network/proxy/auth/404 mean `environment`, and all else falls back to `worker`.
- It applies when `buildFailureCandidates` forms a candidate for a failure signature that repeats (at least two occurrences); the scope comes from that signature's first-seen tool and detail, and `analyze-cases` surfaces it as `scope=<value>` beside the repetition count.
- One failure mode: an environment symptom outside the keyword regex, such as `ETIMEDOUT` or `EAI_AGAIN`, is labeled `worker`, so a reviewer may draft a worker rule for a failure only the environment can fix.
- Reviewer check: `buildFailureCandidates` on two cases sharing an `HTTP 404` failure must yield `suggestedScope: 'environment'`, an `orchestrator_ack` failure must yield `orchestrator`, and an ordinary `edit` failure must yield `worker` (covered by `tests/failure-candidates.spec.ts`).
- Source: `tools/memory/failure-candidates.mjs`, private `suggestedScope(tool, symptom)`, called by `buildFailureCandidates`.
